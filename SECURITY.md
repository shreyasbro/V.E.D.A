# Security Policy

## Supported Versions

V.E.D.A. is actively developed. Security fixes are provided for the latest stable release.

| Version | Supported |
| ------- | --------- |
| Latest stable release | Yes |
| Older releases | Limited |
| Development builds | No |

## Reporting a Security Vulnerability

If you discover a security vulnerability in V.E.D.A., please report it privately instead of creating a public GitHub issue.

### Contact

**Email:** thakurshreyas436@gmail.com

Please include:

- A clear description of the vulnerability
- The affected V.E.D.A. version
- Steps to reproduce the issue
- Expected behavior
- Actual behavior
- Screenshots or logs, if useful
- Any relevant proof-of-concept information

Please do not include passwords, API keys, tokens, or other sensitive information in your report.

## Responsible Disclosure

Please give the maintainer reasonable time to investigate and address a reported vulnerability before publicly disclosing it.

Security testing should only be performed on systems, accounts, and data that you own or have explicit permission to test.

Please do not:

- Access other users' data
- Destroy or modify data
- Disrupt services
- Attempt unauthorized access
- Publish unpatched security vulnerabilities publicly
- Share private credentials or API keys

## API Keys and Credentials

V.E.D.A. allows users to configure their own AI/API credentials.

Never commit personal API keys, passwords, tokens, or other private credentials to the GitHub repository.

If a credential is accidentally exposed:

1. Revoke or rotate the credential immediately.
2. Remove it from the project where appropriate.
3. Report the exposure privately if it creates a security risk.

## Security Updates

Security fixes may be included in future V.E.D.A. releases.

Users are encouraged to keep V.E.D.A. updated to the latest stable release.

Official releases are published through the V.E.D.A. GitHub repository.

## General Issues

For normal bugs, feature requests, UI problems, or general questions, please use GitHub Issues instead of the private security-reporting process.

Thank you for helping keep V.E.D.A. secure.
